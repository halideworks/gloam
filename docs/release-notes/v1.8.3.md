Four calibration fixes, and if you are on Windows 11 25H2 the first one is the reason
your HDR calibration stopped installing. All four were found and verified against real
hardware (MSI MAG 271QP X28, i1 Display Pro).

## Fixed

**HDR profiles install again on Windows 11 25H2.** After updating from 23H2, calibration
would run to completion and then install nothing, with no explanation. 25H2 changed
`ColorProfileGetDisplayList`: it now returns success with **zero** profiles even when the
association is live. Measured directly against a display, adding the association and
setting it as the Extended Display Color Mode default both succeeded, the profile was
written to the registry, and reading the default back returned it correctly, while the
list stayed empty. Gloam required the profile to appear in that list before accepting the
install, so it made a correct association, failed its own verification, rolled the good
association back, and reported that Windows had refused it.

Gloam now treats the default association as authoritative, which it always was: if the
profile is the default in the scope Windows consults, it is associated by definition. The
same false negative was also making Gloam report a live profile as inactive, and making
"retire this profile" silently do nothing and leave stale associations behind. Both are
fixed. This does not change what gets written, only what Gloam believes about it.

**Adaptive calibration no longer fails on a warm display.** On OLED, a full-field white
patch measured straight after a long stretch of dark patches reads well above the panel's
steady state and then decays over seconds as the brightness limiter clamps back. Gloam
was recording the middle of that decay as if it were a real measurement, which made the
run's white anchors disagree by more than the 8% drift limit and failed the whole
calibration with a message telling you to let the display warm up. The display was
already warm; three of the four white anchors agreed to within 0.5%.

Gloam now detects that a reading is still moving and keeps reading until it holds still,
recording only the settled value. This costs nothing on a well-behaved patch: it triggers
only on a genuine one-way drift, and every other bright patch in the failing run was
already stable by its second reading. A patch that never settles is recorded and reported
rather than quietly accepted.

**The measured patch can no longer be interrupted.** Alt+Tab put the task switcher over
the patch mid-reading. Because the probe reads whatever pixels are physically on the
panel, that does not interrupt the measurement visibly, it silently measures the switcher
as though it were the patch. While a reading is in progress Gloam now blocks the shortcuts
that draw over it: Alt+Tab, Alt+Esc, Ctrl+Esc and the Windows keys. Escape still pauses
and cancels, Space still resumes, the arrow keys still nudge the patch, and everything is
released the moment you pause or the run ends. If something does get in front anyway,
Gloam pulls the patch back and records that it happened.

This is not absolute: no user-mode application can block Ctrl+Alt+Del or stop another
program raising its own always-on-top window. It closes the interruption you can trigger
by hand.

**Fixed a freeze when positioning the probe.** Dragging the target could lock the
calibration window: the target would not move and neither Begin Measurement nor Back
would respond, with force-quitting the only way out. The window was holding a mouse
capture it never released.

**The mouse pointer hides over the patch again** once measurement begins, so it cannot be
read along with it. It stays visible everywhere else, including the controls beneath.

---

**Measured-behavior note:** the calibration math is untouched. The settle change alters
which *reading* is recorded for a patch that is still moving when it is measured, which is
a measurement-acquisition fix, not a model change; on a panel whose readings are stable
the recorded values are identical. Profiles built from stable measurement sets are
bit-identical to 1.8.2.

---

**Upgrading:** installed builds update automatically on next launch or restart. Nothing to
do.
